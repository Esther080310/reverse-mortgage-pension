## 一、必须先知道的四处口径差异

网页结果的模拟内核与 `model/CL1模型/` 同源，但**参数取法不同**，因此同一画像会出现两个答案。汇报时若同时引用网页截图与主表数字，务必先看这一节。

### 1. 初始房价值 H0 用的不是同一年

| | 报告主表 `model/CL1模型/outputs/` | 网页 `district_model_lookup.csv` |
|---|---|---|
| H0 来源 | 中国房价行情网 **2026.03 截面估值** | 马克数据网 **2020 年度均价** × 70 ㎡ 参考面积 |
| 黄浦（男 70 岁 · 保证给付） | H0 707.0 万 → **3,231.89 元/月** | H0 632.6 万 → **2,626.15 元/月** |
| 闵行（男 70 岁 · 保证给付） | H0 539.0 万 → **1,980.73 元/月** | H0 347.3 万 → **1,347.03 元/月** |
| 金山（男 70 岁 · 保证给付） | H0 98.0 万 → **269.17 元/月** | H0 126.7 万 → **383.54 元/月** |

差异幅度 −18.7%（黄浦）、−32.0%（闵行）、**+42.5%（金山）**。金山方向相反，是因为 2020 年至今金山均价是下跌的，用 2020 年均价反而抬高了 H0。另有一处易漏的差异：仓库主表里闵行参考面积按改善型取 **110 ㎡**，网页统一改成 **70 ㎡**。

**报告与 PPT 一律以主表为准**；网页数字只用于演示"换区、换年龄、换合同"的交互效果，不进入文字结论。

### 2. 分区波动率改为按档封顶（两侧已统一）

网页原先直接使用 16 个区各自的实测波动率，其中 **静安区 19.53% 明显高于远郊金山 13.85%**，导致静安月领反而低于闵行——房价高 43%、每月少拿 34%，业务上讲不通。该数值本身是真实的（静安 2019 年 91,341 元/㎡ → 2020 年 71,219 元/㎡，单年 −22%，来自挂牌结构跳变），问题在于**九个年度观测点估出的 σ 不足以支撑跨区风险排序**。

现已按档封顶：核心区 11%、城区 13%、远郊 14%。实测低于上限的保留实测值，高于上限的按上限计，原始实测值在参数表 `raw_annual_house_vol` 列与代码行尾注释中完整保留，不在结果层隐藏。被压上限的 10 个区为徐汇、长宁、静安、普陀、杨浦、浦东、宝山、嘉定、青浦、崇明；黄浦、虹口、闵行、金山、松江、奉贤 6 区未触发上限。

封顶后**静安月领由 893.82 元回升到 2,313.80 元**（男 70 岁、LTV 50%、保证给付），重新高于闵行的 1,347.03 元。

残余问题（已披露、未强行抹平）：按 2020 年度均价从高到低排，全表仍有 4 处“房价更低、月领反而更高”——静安 2,313.80 > 徐汇 2,125.29（+8.9%）、普陀 1,501.14 > 虹口 1,452.44（+3.4%）、杨浦 1,540.71 > 普陀 1,501.14（+2.6%）、嘉定 846.11 > 青浦 721.53（+17.3%）。

前三处是**蒙特卡洛噪声**：每区用各自的 `profile_seed` 抽路径，4000 路径下 ES95 的标准误恰是这个量级，不是参数错误；要严格排序需改用共享随机数后全量重跑，会连带改变报告主表数字，本轮未做。

第四处是**档位台阶**，性质不同：嘉定归城区档（σ 上限 13%）、青浦归远郊档（14%），两区房价只差 3%，但实测 σ 每升 1 个百分点月领就降 10.3%–11.4%（同一 H0 只改 σ：青浦 814.11→721.53、嘉定 846.11→756.23）。**档位线画在哪里，线两侧就有约 10% 的月领跳变**，这是封顶方案自身的代价。若业务上不可接受，需重划档位（如嘉定并入远郊档），会改动参数表 `tier` 列与页面分组，属业务决策，本轮未擅改。详见白皮书 §1.1 末段。

这一口径与白皮书《1.1 分区参数覆盖边界》一致，两边不再是分歧。

### 3. 模型脚本是 16 区分支，已与仓库主干合并

包内 `model_api/liability_model.py` 曾把区县预设改成只保留 16 个新键（`huangpu`、`minhang`…），并删掉了仓库主干的三个旧键 `huangpu_small`、`minhang_mid`、`jinshan_small`。而仓库主干有 5 个脚本仍硬依赖旧键（`model_api.py`、`run_liability_scenarios.py`、`run_liability_enhancements.py`、`run_dynamic_ltv_hecm_style.py`、`run_statistical_validation.py` 中的权威种子 `profile_seed("huangpu_small", ...)`），直接用包内版覆盖会让报告主表无法复现。

现已改为**两套键并存**：仓库主干 `liability_model.py` 保留旧三键（2026.03 截面口径，出报告数字），追加 16 个网页键（2020 均价口径），键名白名单集中在 `SEGMENT_CHOICES`，`model_api.py` 的 `--segment` 可选项同步扩为 19 个。两套口径在代码注释与白皮书 §1.1 都有标注。

### 4. 白皮书副本已按用户要求删除

包内原有一份 `02_白皮书_口径权威.md`，内容停留在 2026-10-20 版，落后于仓库 `docs/白皮书_精算模型数据来源与参数.md`（后者补了波动率可复现算法、口径年差披露与分区覆盖边界一章）。两份并存只会制造第三个版本的混淆，故**已删除**，`文件清单.csv` 中对应条目、`00_读我_给网页队友.md` 中的引用行、`01_数据契约与红线.md` 开头的配套说明均已同步修正。

参数与口径一律看 [`docs/白皮书_精算模型数据来源与参数.md`](../docs/白皮书_精算模型数据来源与参数.md)。

## 二、入库排除项与清单口径

按原包自身的 `.gitignore`，以下 3 个文件未纳入版本管理：

- `01_网页源码/dist/data/district_model_lookup_age70.csv` —— 被 `.gitignore` 第 11 行排除；网页运行时不加载它（`app.js` 只 fetch 全量版），全量版已入库。
- 两个 `__pycache__/*.pyc` 字节码缓存。

**`文件清单.csv` 只登记入库的 58 个文件**，上面这 3 项已从清单中剔除。否则任何人 clone 之后校验都会报「清单有而磁盘无」，把正常的排除误判成文件损坏。

另有一处容易漏的坑：本包在仓库根的 `.gitattributes` 里对该目录设了 `-text`，**禁止换行自动转换**。原因是清单记的是逐字节 SHA-256，而 Windows 上 `core.autocrlf=true` 会在检出时把 LF 改写成 CRLF——本包 59 个受管文件里 14 个是 LF、35 个是 CRLF、10 个是二进制，不做限制的话那 14 个在 clone 后必然对不上。关掉转换后，各平台 clone 出的字节与交接时完全一致，清单才能真正校验得通。
